修复业务已处理结果后，多个旧后台 job 仍在聊天空闲时集中补发续接的问题。增加可持久化的通知退休接口，并为同一业务的替代协调器提供 generation 和通知 owner。

- `ack --job-dir ... --reason ...` 确认已处理的完成结果，`cancel-notification` 停止通知并保留正在运行的计算。
- 退休状态与计算、dispatch/turn 证据分开存储；`recover` 不复活已确认、已取消或被替代的通知。
- `launch --workflow ID` 让同一线程、工作目录和锁根下的新一代替代旧通知。独立业务用不同 ID；并行子任务由一个协调器汇总。
- 控制与实际发送共享锁，取消/发送并发时区分未发送、已发送和结果未知，不撤回聊天消息、不盲目重发。
- `status` 新增通知状态、派发结果与实际 worker 锁状态。新续接提示要求先检查当前状态/checkpoint，并在结果处理后 ack。
- 清理当前状态中的过期错误、超时及审批摘要。

验证：36 项隔离 fake RPC/tmux 测试通过，包括取消和发送竞态、回复丢失、工作流替代竞态、计算保留、恢复不复活及旧保护逻辑。未重新执行真实模型或物理 SSH 断线测试。审查依据及边界见 [通知生命周期复盘](https://github.com/VictoriqueDeBlois/background-skill/blob/v2.2.0/docs/notification-lifecycle-review.zh.md)。

安装：解压 `background-job-continuation-2.2.0.zip`，备份后更新同名 skill。升级文件不会改变运行中的 2.1.x worker；新 CLI 会拒绝声称取消不支持控制的旧进程。已停止的旧 job 可用新 helper ack/cancel。已发出的消息不能撤回，本地锁也不能保证与交互式输入之间的原子 idle-only 提交。Linux、原共享 app-server 持续运行及模型服务可访问等要求沿用既有边界。
