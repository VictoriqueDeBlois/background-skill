修复后台任务和续接监控结束后，tmux 仍保留退出窗口的问题。默认在 worker 结束时关闭它的窗口；只有该窗口的任务会话随之退出，结果、日志和续接证据继续保存在任务目录。

本版本的 skill 内容与 [6f114f7](https://github.com/VictoriqueDeBlois/background-skill/commit/6f114f7) 一致。

- 计算完成后继续保持监控，等待续接、审批或最终状态；监控结束或达到等待期限后才关闭窗口。
- 新增 `launch --keep-tmux`，需要调试时保留结束后的窗口，恢复监控时沿用该选择。
- 仅设置 worker pane 的 `remain-on-exit`，不修改全局 tmux 配置，不关闭其他会话。旧版已经留下的窗口不会被追溯删除。
- 窗口关闭后仍可使用 `status` 查询结果，或使用 `recover` 恢复未完成的监控；不重跑计算，不盲目重发续接请求。

验证：22 项隔离测试通过；已安装 helper 的真实 app-server 测试在前端断开、线程卸载后完成自动续接，并在测试清理前确认 tmux 会话自行退出。详情见 [测试报告](https://github.com/VictoriqueDeBlois/background-skill/blob/v2.1.1/test-report.json) 的 `tmux_cleanup_validation`。本次未重新执行物理 SSH 断线测试；2.1.0 的历史结果保留在同一报告中。

安装：下载 `background-job-continuation-2.1.1.zip`，解压后将 `background-job-continuation` 文件夹放入 `${CODEX_HOME:-$HOME/.codex}/skills/`。已有同名 skill 时先备份。ZIP 包含 skill、Python helper、协议说明和 MIT 许可证；附件 `SHA256SUMS` 可用于核对完整性。

环境：Linux、Python 3.10+、tmux，以及支持 `app-server proxy` 的共享 Codex app-server。自动续接要求原 app-server 持续运行且执行主机能访问模型服务。主动退出 App 后不作续接保证；服务器退出后的恢复属于补救措施，未验证 App 完全退出或服务器真正退出、重启。人工审批和客户端专属工具可能等待重连。Windows 和 macOS 适配不包含在本版本中。
